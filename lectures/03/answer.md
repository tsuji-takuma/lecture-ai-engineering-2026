# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 第1回の `app.ask` では「宿題の3レベル」について3回質問して3回とも誤答した（「基礎・応用・発展」など）。また、「どれか1つで完了」という点にも触れなかった。
  - 一方でエージェントは、まず `search_glossary('3レベル')` で用語集を参照し、「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）、どれか1つで完了、原則採点しない」と正しく回答した。回答の末尾には「関連する回：第1回」も付記されていた。
  - 使用モデルはどちらも同じ gemini-3.5-flash-lite である。変わったのはツールを使って正しい情報を取りに行けるようになった点だけであり、それによって回答が正確になった。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` の1回。
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring にある「query には調べたい用語を1つだけ入れる」の指示通り、用語を分けて検索していた。これら2つの呼び出しは、1回の応答の中で同時に行われていた。
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})` の1回。「過学習」に関する問題が出題され、答えは伏せられていた。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 上記3つの質問はいずれも `requests=2` だった（ツールの呼び出し判断で1回、その結果を踏まえた回答生成で1回）。LoRA/QLoRA の質問ではツールを2回呼び出しているが、同一の応答内で並べて呼び出されたため2回で済んでいる。
  - 学習ログの保存（宿題）を含む質問では `requests=3` となった（検索 → 保存 → 回答）。
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int) -> str`（`app/tools.py`）。用語集から指定された回の用語を `random.choice` で1つ選び、`{"question": "「○○」の意味は？", "answer": 定義}` を JSON 形式で返す。
  - docstring：「指定した回の用語から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』『第3回の内容でクイズを出して』のように、確認問題・クイズ・小テストを求められたときに使う。返り値の question を利用者に出題し、answer は利用者が答えるまで見せない。」
  - 用語が存在しない回（第0回・第5回など）では、「第0回の用語は用語集にないため、確認問題を作れません。問題を作れる回: 第1回, 第2回, …」を返すようにした。
  - `INSTRUCTIONS` に追加しなくても、docstring の記述だけで呼び出された。

## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(title: str, content: str) -> str` を作成した。`learning_log/日時-題名.md` に Markdown 形式で保存する。題名に含まれる `/` や `..` は `_` に置き換え、フォルダの外に書き込まれないようにした。
  - `app/agent.py` にて `agent.tool_plain(tools.save_learning_log, requires_approval=True)` として登録し、`output_type=[str, DeferredToolRequests]` とした。
  - CLI に `run_with_approval()` を作成した。結果が `DeferredToolRequests` の場合、`approvals` の呼び出しごとにツール名と引数（題名・本文）を表示し、`[y/N]` で確認を求める。その入力を `DeferredToolResults` にまとめ、`message_history=result.all_messages()` と一緒に `run_sync` をもう一度呼び出す。`y` 以外の入力や、入力できない場合（EOF）は `ToolDenied` として拒否する。
  - `INSTRUCTIONS` に「学習の記録を残すよう頼まれたら save_learning_log で保存する」という指示を追加した。
  - テストを追加した（`tests/`、計20件がパス）。TestModel を使い、承認前はファイルが存在しないこと、拒否した場合は保存されないこと、承認すると1つ保存されることを確認した。
- 結果：
  - 「LoRAとQLoRAの違いを調べて、学習ログに記録して」と指示したところ、検索を2回行った後に `save_learning_log` で停止し、承認待ちになった。`y` と入力すると `learning_log/20261108-220137-LoRAとQLoRAの違い.md` が保存された（`requests=3`）。
  - 「PEFTとは何か調べて、学習ログに記録して」に対して `n` と入力したところ、ファイルは作成されず、モデルから「保存できませんでした」と伝えられて終了した。
  - 保存を依頼していない「LoRAとQLoRAの違いは？」という質問では、`save_learning_log` は呼び出されなかった。
- 気づき・疑問：
  - 当初の docstring に「保存の前に利用者の承認を求める」と記述していたところ、モデルはツールを呼び出さず、チャット上で「記録してもよろしいですか？」と聞き返して終了してしまった（2回試していずれも同様）。承認を「モデル自身が行うこと」と解釈したようだ。「保存してよいかは、ツールを呼んだあとに仕組みの側で確認する。呼ぶ前に会話で確認せず、すぐ呼んでよい」と書き直したところ、すぐにツールを呼び出すようになった。docstring は人間向けの説明ではなく、モデルへの指示として読まれる。
  - 拒否した際の `ToolDenied` のメッセージを「利用者が実行を断りました。」だけにしておくと、モデルが「保存を実行してもよろしいでしょうか？」と再度尋ねてきた。「もう一度許可を求めず、実行しなかったことだけを伝えて」と文言を追加することで再質問を抑えられた。ツールの戻り値もまた、モデルへの指示として効く。
  - 承認する前に、モデルが生成した本文を表示して確認できる仕様は有用だった。保存される内容を人間が見てから判断できる。
  - 同じ「LoRAとQLoRAの違いは？」という質問でも、ツールを2つ追加した後は入力トークン数が 1196 から 1872 に増加した。ツールの説明文は、その質問で使われない場合でも毎回モデルに送られるため、ツールを増やすほど1問あたりのコストが上がることが分かった。
  - 疑問：用語集に「RAG」が存在しないにもかかわらず、`search_glossary('RAG')` は「一致率」と「ファインチューニング」を返した。「一致率」は別名 `inter-rater agreement` の中の「rag」に部分一致し、「ファインチューニング」は定義文に RAG が含まれていたためヒットしていた。モデルは最終的に「用語集にはない」と回答したものの、同一の検索を2回繰り返していた。短い英字の検索語は単語の途中に部分一致しないようにしたほうが、モデルが迷わずに済むのではないか。
