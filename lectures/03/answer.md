- 1つの質問での LLM 呼び出し回数（`requests`）：

## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(title: str, content: str) -> str` を作った。`learning_log/日時-題名.md` に Markdown で保存する。題名の `/` や `..` は `_` に置き換え、フォルダの外に書かないようにした。
  - `app/agent.py` で `agent.tool_plain(tools.save_learning_log, requires_approval=True)` と登録し、`output_type=[str, DeferredToolRequests]` にした。
  - CLI に `run_with_approval()` を作った。結果が `DeferredToolRequests` なら、`approvals` の呼び出しごとにツール名と引数（題名・本文）を表示し、`[y/N]` で聞く。答えを `DeferredToolResults` にまとめ、`message_history=result.all_messages()` と一緒に `run_sync` をもう一度呼ぶ。`y` 以外と、入力できない場合（EOF）は `ToolDenied` で断る。
  - `INSTRUCTIONS` に「学習の記録を残すよう頼まれたら save_learning_log で保存する」を足した。
  - テストを追加した（`tests/`、計20件が通る）。TestModel で、承認前はファイルが無いこと、断ると保存されないこと、承認すると1つ保存されることを確かめた。
- 結果：
  - 「LoRAとQLoRAの違いを調べて、学習ログに記録して」→ 検索2回のあと `save_learning_log` で止まり、承認待ちになった。`y` で `learning_log/20261108-220137-LoRAとQLoRAの違い.md` が保存された（`requests=3`）。
  - 「PEFTとは何か調べて、学習ログに記録して」に `n` → ファイルは作られず、モデルは「保存できませんでした」と伝えて終わった。
  - 保存を頼んでいない「LoRAとQLoRAの違いは？」では `save_learning_log` は呼ばれなかった。
- 気づき・疑問：
  - 最初の docstring には「保存の前に利用者の承認を求める」と書いていた。するとモデルはツールを呼ばず、チャットで「記録してもよろしいですか？」と聞き返して終わった（2回試して2回とも）。承認を「自分でやること」と読んだようだ。「保存してよいかは、ツールを呼んだあとに仕組みの側で確認する。呼ぶ前に会話で確認せず、すぐ呼んでよい」と書き直すと、すぐ呼ぶようになった。docstring は人向けの説明ではなく、モデルへの指示として読まれる。
  - 断ったときの `ToolDenied` のメッセージが「利用者が実行を断りました。」だけだと、モデルが「保存を実行してもよろしいでしょうか？」と聞き直してきた。「もう一度許可を求めず、実行しなかったことだけを伝えて」と足すと止まった。ツールの戻り値も、モデルへの指示として効く。
  - 承認する前に、モデルが作った本文を表示して確認できるのはよかった。保存される中身を人が見てから決められる。
  - 同じ「LoRAとQLoRAの違いは？」でも、ツールを2つ足した後は入力トークンが 1196 → 1872 に増えた。ツールの説明文は、使わない質問でも毎回モデルに送られる。ツールを増やすほど、1問あたりのコストが上がる。
  - 疑問：用語集に「RAG」は無いのに、`search_glossary('RAG')` は「一致率」と「ファインチューニング」を返した。「一致率」は別名 `inter-rater agreement` の中の「rag」に部分一致し、「ファインチューニング」は定義文に RAG を含むため当たっていた。モデルは「用語集にはない」と答えたが、同じ検索を2回繰り返していた。短い英字の検索語は単語の途中に一致しないようにした方が、モデルは迷わないのではないか。
